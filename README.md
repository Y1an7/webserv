# Description
**Webserv** is a HTTP/1.1 server written from scratch in C++98. The primary goal of the project is to understand the underlying mechanics of the HTTP protocol, non-blocking I/O operations, and event-driven architecture.

- The web server can handle various HTTP methods such as GET, HEAD, POST, and DELETE. It can serve static web pages as well as dynamic content generated by CGI. It's capable of handling multiple client connections concurrently through I/O multiplexing.

# Instructions
1. Compilation: run `make` in root directory to generate `webserv` executable.
2. Configuration file: The server requires a configuration file to define ports, hostnames, default error pages, and routing/location rules. You can use the provided default configuration: `default.conf` or `webserv.conf`
3. Execution:
```bash
	./webserv [configuration_file.conf]
```
4. Testing: Once running, you can test the web server using a web browser or curl commands on specified method.

# key concept
## OS & Kernel Layer (The Engine)
- Event-Driven I/O Multiplexing: The core engine leverages Linux's epoll system call. This allows a single thread to concurrently manage thousands of client connections and CGI pipes without hanging or stalling.
- Non-Blocking I/O: Every socket and CGI pipe is strictly set to non-blocking mode. This ensures the server never hangs on a slow client or a stalled script, maintaining maximum concurrency and resource efficiency.
## Network Layer (Connection Management)
- TCP Socket Handling: Robust management of network interfaces and client connections by directly orchestrating POSIX socket APIs, including socket(), setsockopt(), bind(), listen(), and accept().
## HTTP Protocol Layer (The Rules of Web)
- Virtual Hosting: Hosts multiple domains or websites on the exact same IP and port by parsing and resolving the HTTP Host header.
- Comprehensive Method Parsing: Fully supports and processes standard HTTP methods (GET, HEAD, POST, DELETE), ensuring strict adherence to RFC messaging formats.
## Application & Resource Layer (Content Delivery)
- Static Assets & Directory Management: Swiftly delivers static files (HTML, CSS, JS). If a directory is requested without a default index file, the built-in Autoindexing dynamically generates an HTML directory listing.
- File Management: Provides server-side file manipulation, allowing users to upload resources via POST or delete them via DELETE based on location permissions.
- CGI (Dynamic Content): Acts as a bridge between the HTTP server and external executable scripts (like Python or PHP). This layer pipes HTTP payloads into standard input and extracts headers/bodies from standard output, enabling complex features like Cookies, Session Management, and user authentication.
